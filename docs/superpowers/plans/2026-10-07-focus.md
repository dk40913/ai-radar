# 安裝時設定讀者與關注主題 — Plan

**Goal:** 雷達目前寫死成「AI Agent 工程師」的關注方向。讓安裝的人可以填自己的讀者身分與關注主題，影響 arXiv 篩選、挑選評分與每條的第四段標題；不填就維持現在的預設。

**Spec（Herb 2026-10-07）：** 「目前搜尋的方向應該是我現在的 AI AGENT 相關知識，要不要設定成在初始安裝的時候可以給使用者輸入有興趣的主題方向？」

## Global Constraints

- config.json 新增三個鍵（其他鍵不變）：
  - `reader`：字串，預設 `"AI Agent 工程師"`
  - `focus`：字串，預設 `"AI Agent、LLM 推論與部署、RAG、本地模型、agent 框架與工具"`
  - `arxiv_keywords`：字串陣列，預設 `[]`；空陣列＝用 `fetch_sources.py` 內建的 `ARXIV_KEYWORDS`
- 不改來源清單、版面、分群、GitHub AI Agent 週榜（週榜維持 agent 專屬，這是已知上限，README 要寫明）。
- 預設值下，產出的行為必須和現在完全相同（SKILL 文字代入預設值後語意不變；arXiv 篩選結果不變）。
- 出貨檔案不得含個人字串（`tests/test_no_personal.py` 照跑）。
- 測試：`uv run --quiet --with markdown python3 -m unittest discover -s skill/tests && python3 -m unittest discover -s tests`（repo 根目錄）。

## Task 1: 讀者與關注主題可設定

Files: `install.sh`、`skill/scripts/fetch_sources.py`、`skill/SKILL.md`、`skill/config.example.json`、`vault-template/AI知識雷達/CLAUDE.md`、`INSTALL.md`、`README.md`、`tests/test_install.py`、`skill/tests/`（新測試）、本 plan 不用改。

1. `install.sh`：新增旗標 `--reader TEXT`、`--focus TEXT`、`--arxiv-keywords "k1,k2,..."`（逗號分隔，去掉前後空白與空項目，轉小寫）。未給時寫入 Global Constraints 的預設值。寫進 config.json（JSON 用 python3 產生，中文用 UTF-8，`open(..., encoding="utf-8")`）。安裝摘要多印一行 `focus:` 顯示 reader 與 focus。
2. `fetch_sources.py`：`fetch_arxiv` 用的關鍵字改由一個小函式決定：讀 `Path(__file__).resolve().parent.parent / "config.json"` 的 `arxiv_keywords`，非空就用它（轉小寫），否則用內建 `ARXIV_KEYWORDS`；config 不存在或格式壞掉也退回內建。`_arxiv_relevance` 改成接收關鍵字清單參數（或等效做法），其他來源不動。註解「只留跟 AI Agent 工程相關的」改成中性說法。
3. `SKILL.md`：
   - 第 0 步讀設定多兩個變數 READER、FOCUS（說明預設值）。
   - 第 3 步評分「與 AI Agent 工程師的相關性（AI Agent、LLM 推論與部署、RAG、本地模型、agent 框架與工具）」改成「與 READER 的相關性（FOCUS）」。
   - 第 5 步固定指令的第四段標籤 `**對 AI Agent 工程師的意義**` 改成 `**對 <READER> 的意義**`，並在派 subagent 的清單說明要把 READER 代入（和 `<補抓方式>` 同樣的代入方式）。
   - 只改這三處，其他文字不動。
4. `vault-template/AI知識雷達/CLAUDE.md`：四段描述的第四段改成「**對 <讀者> 的意義**（讀者是 config 的 `reader`，預設 AI Agent 工程師）」。
5. `skill/config.example.json`：加三個鍵與預設值。
6. `INSTALL.md` 第 2 步：多問一題「週報要以誰的角度、關注哪些主題？（直接 Enter＝預設：AI Agent 工程師，關注 AI Agent、LLM 推論與部署、RAG、本地模型、agent 框架與工具）」。使用者給了自訂主題時，由安裝的 agent 依主題產生 15–30 個英文小寫 arXiv 關鍵字（會被拿來對論文標題與摘要做子字串比對，所以要用常見詞形，例如 `diffusion`、`medical imag`），先給使用者看、同意後用 `--arxiv-keywords` 傳入；用預設就不帶這三個旗標。第 5 步的指令範例加上這三個選用旗標。
7. `README.md`：在「安裝」段落提到可自訂讀者與主題；「需求」或適當位置加一句已知上限：來源本身是 AI 綜合來源，自訂主題只影響篩選、評分與撰稿角度，「GitHub AI Agent 週榜」固定是 agent 主題；「換模型」那段旁補「換主題」：重跑 install.sh 帶新的 `--reader`／`--focus`／`--arxiv-keywords`（不帶就回到預設，跟其他旗標一樣要每次帶齊）。
8. 測試：
   - `tests/test_install.py`：不帶旗標時 config 含三個預設值；帶 `--reader 醫療影像研究員 --focus "醫學影像、診斷模型" --arxiv-keywords " Medical Imag, segmentation,,MRI "` 時寫入 `["medical imag","segmentation","mri"]` 與對應字串。既有對 config 全等比對的測試要一起更新。
   - `skill/tests/` 新測試：config 有 `arxiv_keywords` 時 `_arxiv_relevance`（或新的關鍵字選擇函式）用它；空陣列、檔案不存在、JSON 壞掉時用內建清單。用暫存目錄與 monkeypatch config 路徑，不碰真的 `~/.claude/skills/ai-radar/config.json`。
   - `tests/test_skill_md.py`（已存在）加一個檢查：SKILL.md 不再出現 `對 AI Agent 工程師的意義`，且含 `READER`。
